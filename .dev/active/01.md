# Subprocess Timeout & Retry Wrapper for Rustup Commands

**Status:** Planned
**Priority:** Medium
**Created:** 2026-02-19

## Context

`rustup update` can hang due to network issues (DNS delays, CDN routing, connection stalls). Empirically, canceling and retrying often succeeds faster because:

- Fresh connection may hit a better CDN edge
- DNS cache is warm
- CDN cache may be primed from first attempt

Currently, `RustSpace.setup_tools()` and `RustSpace.update()` call `rustup update` without any timeout, potentially hanging indefinitely.

## Goals

- Add automatic timeout for `rustup update` calls
- Auto-retry on timeout (leverage "second process wins" pattern)
- Keep implementation simple and reusable

## Implementation Plan

### Option A: Wrapper function in `rust.py`

```python
import subprocess

def _run_with_retry(ctx, cmd: str, timeout: int = 60, max_retries: int = 3) -> None:
    """Run command with timeout and auto-retry on timeout."""
    for attempt in range(max_retries):
        try:
            ctx.run(cmd, timeout=timeout)
            return
        except Exception as e:  # Adjust based on what ctx.run raises
            if attempt == max_retries - 1:
                raise
            console.echo(f"[yellow]Timeout on attempt {attempt + 1}, retrying...[/yellow]")
```

### Option B: Add retry support to `ctx.run` directly

If `ctx` is from nox/invocations, check if they support native timeout/retry parameters.

### Recommended: Option A

Simpler, self-contained, no changes to core infrastructure.

### Changes to `rust.py`

1. Add `_run_with_retry()` helper method
2. Update `setup_tools()`:
    ```python
    def setup_tools(self) -> None:
        super().setup_tools()
        self._run_with_retry("rustup update")
        self._run_with_retry("rustup install stable")
    ```
3. Update `update()`:
    ```python
    def update(self) -> None:
        super().update()
        self._run_with_retry("rustup update")
        self.ctx.run("cargo update")
        check_rust_version_matches_stable(self.ctx)
    ```

## Testing Strategy

- Unit test: Mock `ctx.run` to raise timeout on first N calls, succeed after
- Manual test: Run `bake update` with network throttling to verify retry behavior

## Success Criteria

- `rustup update` auto-retries up to 3 times with 60s timeout each
- User sees feedback on retry attempts
- No indefinite hangs
