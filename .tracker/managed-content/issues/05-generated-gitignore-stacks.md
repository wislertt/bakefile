# 05: Generated `.gitignore` stack sections

Status: resolved

Blocked by: 04

Spec: `.tracker/managed-content/spec.md`. Decision: `docs/adr/0006-managed-files-and-bake-lock.md`.

**What to build:** `BaseSpace`'s `.gitignore` gets its stack section (the part repos now paste from toptal) from a hook that lists [github/gitignore](https://github.com/github/gitignore) templates, so child Spaces add or remove templates with `super()`. No templates ship in the bakefile package: sync fetches them from github/gitignore when the section must change, and the committed `.gitignore` is the cache. `lint` never touches the network.

Lifecycle:

| Moment                                 | Command                                       | Stack section                                                | Network |
| -------------------------------------- | --------------------------------------------- | ------------------------------------------------------------ | ------- |
| First time                             | `bake setup-dev` (runs mc sync)               | fetched from the latest `main` and written                   | yes     |
| Normal work                            | `bake lint`, `bake setup-dev`, `bake mc sync` | kept byte for byte                                           | no      |
| Template list changed                  | next `mc sync` or `setup-dev`                 | fetched again with the new list, at the section's commit     | yes     |
| Template list differs from the header  | `bake lint`                                   | drift, "run `bake mc sync`"                                  | no      |
| Same templates, pick up upstream fixes | `bake update`                                 | fetched again from the latest `main`; the header's SHA moves | yes     |

- [x] `_get_gitignore_templates()` hook on `BaseSpace` returns github/gitignore template paths without `.gitignore` (`"Python"`, `"Global/macOS"`); child Spaces add templates and may remove a parent's, composed with `super()`
- [x] Defaults: `BaseSpace` `Global/macOS`, `Global/Windows`, `Global/VisualStudioCode`; `PythonSpace` adds `Python`; `RustSpace` adds `Rust`; no other Space adds templates
- [x] toptal's `ssh` and `rust-analyzer` stacks have no github/gitignore template: their lines move to `BaseSpace`'s `_get_gitignore_lines()` (`ssh`) and `RustSpace`'s `_get_gitignore_lines()` (`rust-analyzer`)
- [x] The section: templates deduped and sorted by path (so hook composition order never changes the file), each under a `### <path> ###` line, after a line naming the upstream commit (`# Created from github/gitignore@<sha>`) a line naming the templates (`# Templates: Global/VisualStudioCode, Global/Windows, Global/macOS, Python`) and a line saying how to change them (`# To change the templates, override _get_gitignore_templates() in bakefile.py`), and before a matching end line; rendered as a hook-backed bakefile value at the top of the file
- [x] Fetch: resolve `main`'s SHA once (`git ls-remote`, no API rate limit), then fetch each template from `https://raw.githubusercontent.com/github/gitignore/<sha>/<path>.gitignore`; send nothing but the template paths
- [x] Sync fetches only when the file has no section, the header's template list differs from the hook's, or a refresh is asked for; otherwise it keeps the committed section byte for byte, with no network
- [x] `bake update` runs its closing sync as `mc sync --refresh`, so same-template upstream fixes arrive there as a reviewable diff; `setup-dev`, a plain `mc sync` and `lint` never refresh. `--refresh` is a public, generic option: it passes `Fetch.REFRESH` to `_get_managed_values()`
- [x] `lint` compares the header's template list with the hook's and reports drift without fetching; a hand edit inside the section is drift too (through `bake.lock`, or however the lock already catches edits to hook-backed values)
- [x] A failed fetch (offline, proxy, or an unknown template's 404) exits 2 naming the template and URL, and writes nothing
- [x] Engine: the hook can read the existing section from the current `.gitignore` (its one network-backed, file-cached value); recorded in ADR 0006 as an exception to bakefile values being pure functions of the Space
- [x] Adoption keeps a hand `.gitignore` verbatim in the adopt block, toptal section included; no migration from toptal
- [x] Tested with a fake fetcher (no test touches the network) and made-up child Spaces: one adds a template, one removes a parent's; checks the section, stable order, kept editable blocks, no drift afterwards; a second sync with the same templates does not fetch; a changed list fetches; a refresh fetches and moves the SHA; a failed fetch exits 2 and writes nothing; lint reports a mismatched list without fetching
- [x] Spec and ADR 0006 updated (fetch at sync, the `.gitignore` as cache, refresh on `bake update`, Global templates rendered into each repo rather than left to a global gitignore)
- [ ] After release: update `02-wealth/gitignore-pattern.md` in the agent-home wiki (bake renders the stack section from github/gitignore in bakelib repos; the hand `curl` stays for repos without bakelib)

## Resolved questions (2026-11-25)

- Source: github/gitignore (CC0, active), not toptal. toptal's template repo (`github.com/toptal/gitignore`) returns 404 and `toptal/gitignore.io` last synced templates in July 2023, so toptal's API serves frozen content.
- Not shipped in the package: no maintained Python package bundles github/gitignore (`git-ignore` is a 2019 snapshot; `pygic` and `gitignorio-cli` bundle toptal's content), a pinned SHA in the package goes stale until someone bumps it, and shipping every template would add about 41% to the wheel even as one JSON file.
- Fetched at sync, not at every run: `lint` runs in CI on every commit, so it must work offline and give the same answer every time. The committed section is the cache, and its header records the upstream SHA.
- Raw files, not the REST API: `GET /gitignore/templates` serves only the 164 root templates (no `Global/`), cannot pin a commit and allows 60 unauthenticated requests an hour.
- Same-template refresh rides on `bake update`, which already upgrades dependencies and needs the network.
- `BaseSpace` defaults: the wiki's gitignore pattern (macOS, Windows, VS Code, ssh), not Linux or JetBrains. github/gitignore's README suggests a global gitignore for `Global/` templates; rendering them into each repo protects contributors who never set one up.

## Comments

- 2026-11-25: A first implementation (toptal stacks shipped at `bakelib/space/managed/gitignore_stacks/`, a hand-run `bake refresh-gitignore-stacks`) is in the working tree, uncommitted. Rework it: drop `gitignore_stacks/`, `scripts/gitignore_stacks.py`, the refresh command and `TemplateSuite`'s subfolder-as-data rule with its test.
- 2026-11-25: CRs cannot pass through the engine (`normalise` and `splitlines` would split them). github/gitignore's `Global/macOS` has `Icon[\r]`, with the CR mid-line. Decided: a fetched line that `splitlines()` would split is dropped, and trailing whitespace is stripped. `Icon?` was rejected because it also ignores a file named `Icons`.
- 2026-11-25: Implemented in `bakelib/space/gitignore.py`; the engine is unchanged. The hook reads the committed section from `.gitignore` itself, and a context variable (`fetching(Fetch...)`) says whether it may fetch: never by default (`lint`, `mc lock`), when needed in sync, and refresh in `bake update`. Offline with a changed list, the hook returns a one-line "not fetched yet" placeholder, so `lint` reports drift.
- 2026-11-25: Hand edits: the end line holds a sha256 digest of the section, so a hand edit is caught without `bake.lock` changes. Sync re-fetches at the section's own commit and the engine's existing note says the hand edit is reverted.
- 2026-11-25: A changed list or a repaired hand edit fetches at the section's recorded commit, not the latest `main`, so the diff holds only the template that changed. Only the first sync and `bake update` resolve `main`.
- 2026-11-25: `bake update` runs its closing sync in a subprocess, so the refresh goes through a hidden `mc sync --refresh-gitignore` option. It is left out of `--help` to match "no user-facing flag".
- 2026-11-25: Tests stay offline: `TemplateSuite` and an autouse fixture in `tests/unit/conftest.py` swap in `STAND_IN_GITIGNORE` (`bakelib.managed_content.testing`), which renders each template as one line naming it. Checked once by hand against GitHub: a real sync, a second sync and the drift check pass, and an unknown template exits with the 404 URL.
- 2026-11-25: Dropped the toptal section removal on adoption and the engine's adopt filter. No repo had bake-managed content before, so there is nothing to migrate: a hand `.gitignore` is adopted verbatim, and a pasted toptal section is deleted by hand.
- 2026-11-25: Layout reworked after review of the expected file. Three parts separated by blank lines: the stack section, the Space lines, then one editable block `repo` (adopt) at the end, so hand and tool-appended rules win. The standard lines moved from fixed template text into `_get_gitignore_lines()`, now a set like the templates hook, so a child Space can remove a parent's line; written sorted with `!` lines last, because only negations depend on order. The start line split into a commit line, a templates line and a line saying to override `_get_gitignore_templates()` in `bakefile.py`; the Space lines heading says the same for `_get_gitignore_lines()`, so a reader without bakelib context knows where to change them. The expected file renders real templates from a snapshot of three `Global/` templates at a fixed commit (`tests/unit/bakelib/managed_content/github_gitignore/`), passed to `TemplateSuite(gitignore_upstream=...)`.
- 2026-11-25: Design review, first pass. The context variable (`fetching(Fetch...)`), the second one that swapped the upstream (`using_upstream`) and the hidden `mc sync --refresh-gitignore` are superseded by a public, generic `mc sync --refresh`, which `bake update` runs. Tests replace the upstream by patching `BaseSpace._get_gitignore_upstream()`. This pass also gave the engine a `FetchedValue` kind (`kept()` offline, `fetch()` on the network) and made `ManagedFile.values` a mapping from name to function; both were dropped in the second pass below.
- 2026-11-25: Design review, second pass. The engine takes plain text and knows nothing about fetching. `ManagedFile.values` is a tuple of names again, and the Space gives every value's text in one mapping, `_get_managed_values(fetch)`, which replaces the lookup of `_get_<name>()` hooks or settings (`_get_bakefile_value` is gone). The command passes the fetch mode as the argument: `Fetch.NEVER` from `lint` and `mc lock`, `WHEN_NEEDED` from `mc sync`, `REFRESH` from `mc sync --refresh`. `stack_section()` in `bakelib/space/gitignore.py` reads the committed section, fetches only when the mode allows it, and gives the one-line "not fetched yet" text under `NEVER`, so `lint` reports drift. `TemplateSuite(gitignore_upstream=...)` and `STAND_IN_GITIGNORE` in `bakelib.managed_content.testing` stay.
- 2026-11-25: Two fixes. The digest on the end line now covers the start lines too: a hand edit of the commit or templates line used to leave the section "intact", so `lint` passed with a template missing. And the sync note for a rewritten value now says "hand edits inside it are not kept", where it used to claim "a hand edit inside it is reverted" even when only upstream moved.
- 2026-11-25: Review fixes. A hand edit that breaks a start line or the end line is still repaired at the section's commit, as long as its commit line can be read; only then does sync fall back to the latest `main`. The section is read only from above the editable block (`# (editable) below this line`), so a copy pasted into the `repo` block or sitting in a hand file to adopt is never the cache. A 404 at the section's kept commit says the template may have been added later and to run `bake mc sync --refresh`. A download cut short (`http.client.IncompleteRead`) exits 2 like any other failed fetch. `Fetch` moved from the engine to `bakelib/space/utils/__init__.py` (exported from `bakelib.space`), so `bakelib.managed_content` knows nothing about fetching. The stack section code moved to `bakelib/space/utils/gitignore.py`, since neither is a Space.
- 2026-11-25: The command layer is one class. `ManagedContent(root, managed_files, values)` in `bakelib/managed_content/content.py` (renamed from `run.py`) replaces `run_lock`, `run_sync` and `run_check`, which all took those same three inputs; they are now its `lock`, `sync` and `check` methods. The Space builds it in `_managed_content(fetch)`, and `lint` uses one object for its lock and its check, so it builds the values once.
