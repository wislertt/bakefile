# Managed content: end-to-end runbook

The demo code was removed after the user ran the demo. To run it again, restore it with `git checkout 7aacd1f -- scripts/demo tests/unit/scripts/test_demo.py bakefile.py` (7aacd1f is the last commit that has it), then delete it again before committing.

Temporary. `bake -b demo step<N>` walks a repo maintainer through normal use of managed files, then the rare cases (a hand edit to fixed text and its fixes, detach and re-attach, a dropped file), with real `bake` commands, on the disposable branch `demo/managed-content-e2e`. Code: `scripts/demo/` (templates in `managed/`, the `DemoFiles` mixin in `files.py`, the steps in `bakebook.py`). Delete it, this runbook and the `demo = DemoBakebook()` lines in `bakefile.py` when the feature closes.

Each step does the maintainer's action, runs the `bake` commands as subprocesses with their output and exit code shown, checks each result (`PASS`, or `MISMATCH` and exit 1) and names the next step. A step that changes files stages them (`git add -A`) and leaves them uncommitted, so its diff shows in the IDE; it records the commit message in the git dir (`bake-demo-pending`), and the next step first commits the staged changes with that message. Step 1 clears a message left by an aborted run. `bake -b demo all` runs every step in order and stops at the first mismatch; `bake -b demo step14` then returns to the starting branch once the tree is clean.

The demo files are `demo/alpha.toml` (template `scripts/demo/managed/alpha.toml`, empty editable block `local`) and `demo/beta.yml` (template `scripts/demo/managed/beta.yml`, editable block `settings`). Demo commits skip the pre-commit hook (`--no-verify`); the steps run `bake lint` themselves.
